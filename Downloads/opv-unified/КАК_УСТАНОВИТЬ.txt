ЕДИНЫЙ СЕРВИС — Ипотека/ОПВ + Депозиты + Бланки + Парсер
========================================================

ЧТО В ПАПКЕ:
  Index.html          — твой фронтенд + 3 новые вкладки + подписка (ЗАМЕНЯЕТ старый Index)
  Code_additions.gs   — код подписки и отдачи инструментов (добавить в Code.gs)
  DepositCalc.html    — калькулятор вознаграждения по депозитам
  DepositBlanks.html  — бланки переуступки депозита
  preview.html        — витрина для превью (открывается двойным кликом, без сервера)

--------------------------------------------------------
ПОСМОТРЕТЬ СРАЗУ (без установки):
  Двойной клик по preview.html — откроется в браузере.
  Демо-ключи: DEMO (активна), SOON (истекает), EXPIRED (экран оплаты Kaspi).

--------------------------------------------------------
УСТАНОВКА В GOOGLE APPS SCRIPT (по шагам):

1. Открой свой проект Apps Script (script.google.com → твой проект «ОПВ»).

2. Файл Index.html:
   — открой файл Index (HTML) в проекте;
   — выдели весь старый код (Ctrl+A) и вставь содержимое Index.html из этой папки.

3. Файл Code.gs:
   а) открой Code.gs из этой папки Code_additions.gs;
   б) скопируй ВЕСЬ его текст в конец своего Code.gs;
   в) в старом Code.gs УДАЛИ три старые функции (их заменяют новые):
        function _getClientsSheet_()   ← старую удалить
        function apiLogin(...)          ← старую удалить
        function apiMe(...)             ← старую удалить
      (новые версии этих функций уже есть в добавленном коде).

4. Два новых HTML-файла в проекте:
   — «+» рядом с файлами → HTML → назови DepositCalc → вставь DepositCalc.html;
   — «+» → HTML → назови DepositBlanks → вставь DepositBlanks.html.
   ВАЖНО: имена ровно DepositCalc и DepositBlanks (без .html в поле имени).

5. Настройки в Code.gs (блок «НАСТРОЙКИ» вверху добавленного кода):
        KASPI_PHONE         — твой номер Kaspi для оплаты
        KASPI_NAME          — получатель
        SUB_PRICE           — цена подписки (по умолчанию 2990)
        PARSER_DOWNLOAD_URL — ссылка на архив парсера ПКБ/ГКБ (можно оставить пустым)

6. Опубликовать: Развернуть → Управление развёртываниями → карандаш →
   Новая версия → Развернуть.

--------------------------------------------------------
КАК ПРОДАВАТЬ ПОДПИСКУ (ручная активация):

В Google-таблице лист «Клиенты» теперь колонки:
  A Ключ | B Имя | C Активен(да/нет) | D DeviceId | E Дата привязки | F Действует до

Чтобы дать доступ после оплаты на Kaspi:
  1. Впиши строку: Ключ (любой пароль) | Имя клиента | да | (пусто) | (пусто) | дату окончания.
  2. В колонку F поставь дату, до которой действует подписка (напр. 18.08.2026).
     — Если F пустая = подписка бессрочная (пока C = «да»).
  3. Когда дата в F прошла — вход автоматически блокируется и клиенту
     показывается экран оплаты Kaspi. Продлил оплату — меняешь дату в F.

Отключить досрочно: поставь в колонке C «нет».
Перепривязать к другому устройству: очисти колонку D (DeviceId).

--------------------------------------------------------
ПАРСЕР ПКБ/ГКБ:
  Это отдельная десктоп-программа (папка PKB_App_v8). В браузере не работает.
  В сервисе — вкладка «Парсер ПКБ/ГКБ» со ссылкой на скачивание
  (задаётся в PARSER_DOWNLOAD_URL). Можно залить архив на Google Drive
  и дать ссылку «доступно всем по ссылке».

--------------------------------------------------------
ПОДПИСКА НА ПАРСЕР «ПО ВРЕМЕНИ» (тот же ключ и срок, что и веб-сервис):

Парсер теперь может требовать ключ доступа и блокироваться после
окончания подписки — как веб-сервис. Проверка идёт через то же
веб-приложение Apps Script (лист «Клиенты», колонка «Действует до»).

Чтобы ВКЛЮЧИТЬ проверку в парсере:
  1. Разверни веб-приложение Apps Script так, чтобы работал POST:
       Развернуть → Управление развёртываниями →
       «Выполнять как: Я», «Доступ: Все» (даже без входа).
       Скопируй URL вида https://script.google.com/macros/s/…/exec
  2. В программе парсера открой файл settings.json и впиши:
       "license_url": "СЮДА_URL_/exec"
     (или задай его в коде app.py в DEFAULT_SETTINGS)
  3. При запуске программа спросит ключ доступа (тот же, что для сервиса),
     привяжет его к компьютеру и будет проверять срок при каждом запуске.

ВАЖНО — защита от самоблокировки:
  • Если "license_url" пустой — проверка ОТКЛЮЧЕНА, программа работает как раньше.
  • После первой успешной онлайн-проверки срок кэшируется: программа
    работает и без интернета, пока не пройдёт дата в «Действует до».
  • Когда срок вышел — показывается окно с реквизитами Kaspi и просьбой продлить.

Отключить/продлить: как и для веб-сервиса — колонки «Активен» и «Действует до»
в листе «Клиенты». Перепривязать к другому ПК — очисти DeviceId у клиента.

--------------------------------------------------------
ЗАЩИТА ОТ ВЗЛОМА ПАРСЕРА (3 обязательных шага):

ШАГ 1 — СЕКРЕТ ПОДПИСИ (чтобы нельзя было подделать срок):
  Придумай длинную случайную строку (60+ символов, буквы+цифры) и впиши
  ОДНУ И ТУ ЖЕ в двух местах:
     • Code.gs  → var LICENSE_SECRET = '...';
     • license_gate.py → LICENSE_SECRET = "..."
  Сервер подписывает срок этим секретом, программа проверяет подпись.
  Подделать дату в файле настроек без секрета невозможно — подпись не сойдётся.
  Секрет НИКОМУ не показывай и не выкладывай.

ШАГ 2 — ВПИШИ URL В КОД (чтобы нельзя было выключить проверку):
  В license_gate.py → LICENSE_URL = "https://…/exec"
  (не только в settings.json). Тогда правкой settings.json проверку не отключить.

ШАГ 3 — СОБЕРИ .EXE (чтобы не редактировали исходный код):
  Не раздавай клиентам .py-файлы! Собери один .exe:
     pip install pyinstaller
     pyinstaller Anketa_PKB.spec
  Готовый .exe будет в папке dist\. В нём код и секрет спрятаны в бинарнике —
  обычный пользователь не сможет его открыть и поправить.

ЧЕСТНО О ПРЕДЕЛЕ ЗАЩИТЫ:
  Эти 3 шага останавливают 99% пользователей: нельзя выключить проверку,
  подделать срок, скопировать на второй ПК (привязка к устройству). Абсолютной
  защиты у офлайн-программ не бывает — очень опытный человек теоретически может
  «пропатчить» .exe. Но для продажи обычным клиентам этого более чем достаточно.
